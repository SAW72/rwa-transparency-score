# API history storage (package A4)

Local **Postgres-ready** schema + migrations for paid API history. SQLite remains the running path. **No hosted / paid Render Postgres** is provisioned here.

## What runs today

| Piece | Behavior |
|---|---|
| Default DB | SQLite at `RWA_API_DB_PATH` (default `data/rat_api.sqlite`) |
| Runner | `rwa_score.api.migrations.apply_sqlite_migrations` on `Store` startup |
| History rows | `score_history` — ticker, scored_at, score, band, payload_json, payload_hash, optional **`key_id`** (tenant) |
| Replay | `GET /v1/history/{ticker}` (paid) reads that key’s rows |

Render’s filesystem is still ephemeral. A disk or a later self-hosted Postgres is required before keys/history survive deploys. This PR does **not** change `render.yaml` or add a paid database.

## Revisions

1. **`001_initial`** — keys, usage, history, watchlists, webhooks, last_bands (tenant PK), deliveries.
2. **`002_history_tenant`** — nullable `score_history.key_id` + index `(key_id, ticker, scored_at)` so history can be isolated per API key without a hosted DB.

Applied versions live in `schema_migrations`.

## Postgres later (self-host only)

```bash
python -m rwa_score.api.migrations --dialect postgres
```

Prints `001` + `002` in Postgres dialect (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, `DOUBLE PRECISION`, `ADD COLUMN IF NOT EXISTS`). Apply with your own `psql` when you choose to run Postgres **yourself**. Do not point the free Render web service at a paid Render Postgres from this package.

`RWA_API_DATABASE_URL` is accepted on `ApiSettings` as a **future** hook and is **not** opened by `Store`. SQLite `RWA_API_DB_PATH` stays authoritative.

## Compatibility

Existing SQLite files created before this runner still work: `001` uses `CREATE TABLE IF NOT EXISTS`, then `002` adds `key_id` when missing. The older unscoped `last_bands` table is still rewritten by `Store._migrate_last_bands`.
